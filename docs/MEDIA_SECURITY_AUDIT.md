# Vimivo — Media Security & Codec Dependency Audit Report

> [!NOTE]
> Authoritative security and licensing audit covering media probing, native library loading, untrusted bitstream parsing, and supply-chain dependencies under **Milestone 45** and **Milestone 46**.

---

## 1. Threat Model & Untrusted Media Input Boundary

Media players parse complex, binary file formats often generated by untrusted third parties. Vimivo classifies all external media files, container headers, ID3/Vorbis tags, and subtitle streams as **untrusted data**.

```
[Untrusted Media File / Stream]
              │
              ▼
[Security Barrier: Bounded Header Sniffer & Argument-Safe Prober]
  ├── Max header read: 4096 bytes
  ├── Zero shell interpolation (execFile / ProcessBuilder array arguments)
  └── Strict execution timeout: 2,500 ms
              │
              ▼
[Native Decoder Engine: libmpv / Media3 / AVFoundation]
  ├── Bounded demuxer cache: 32 MB
  ├── Dynamic memory leak prevention
  └── Controlled native library loader paths
```

## 2. Defensive Probing Architecture

### No external programs
Desktop Media Info (`DesktopMediaProbeService`) and library metadata/thumbnails (`DesktopVideoInspector`) read files
in-process through the bundled LGPL libmpv/FFmpeg (`MpvMediaInspector`, ADR-004). No subprocess and no shell is ever
started, so there is no command line to inject into.
- Filenames reach libmpv as a separate argument of the documented `mpv_command` client API (`loadfile <path> replace`),
  never interpolated into a string.
- Each inspection uses its own short-lived handle with `config=no`, no scripts, no terminal and no hardware decoding.

### Time bounds
- **Deadline**: every inspection waits at most 5 s for libmpv to load the file (and 1.5 s for the first decoded frame's
  colour parameters); a file that never loads is reported as unopenable and the handle is destroyed.
- **Fast-Path Sniffing**: Files under 64 bytes, and files libmpv cannot open, are classified from their first bytes in memory.

## 3. Native Library Loading & DLL Hijacking Prevention

Vimivo enforces strict security boundaries on native binary loading:
1. **No Media Directory Loading**: Under no circumstances are `.dylib`, `.so`, or `.dll` files loaded from media directories or working paths.
2. **macOS Loader Security**:
   - `MpvNativeLoader` searches only trusted system directories (`/opt/homebrew/lib`, `/usr/local/lib`) or verified packaged application Frameworks.
   - Preserves macOS System Integrity Protection (SIP) and hardened runtime entitlements.
3. **Windows DLL Hijacking Defense**:
   - DLL loading uses explicit absolute paths or system `SetDllDirectory("")` to eliminate current-working-directory DLL hijacking vulnerabilities.
4. **Linux Library Security**:
   - Packaged binaries use clean `RUNPATH` pointing strictly to bundled lib directories, avoiding arbitrary preload hijacking.

---

## 4. Subtitle Security & Execution Prevention

- **Subtitle Vector Sanitization**: Subtitle formats that support advanced styling (such as ASS/SSA) are parsed strictly by `libass` or text rendering engines as visual display vectors and text strings.
- **No Script Execution**: Embedded subtitle events are never passed to script engines or command runners.
- **Safe Parser Limits**: Memory allocated for subtitle cue blocks is strictly bounded to prevent heap exhaustion attacks from malicious 100MB subtitle sidecars.

### DRM & Access Control Integrity
Vimivo complies fully with product boundaries:
- **Zero DRM Bypass**: Vimivo does not include tools or mechanisms to bypass DRM, Widevine, FairPlay, or access controls.
- **Zero Telemetry**: No media hashes, file paths, listening history, or viewing metrics are ever transmitted over the network.
